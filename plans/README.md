# Animation plans

Generated by `improve-animations` from the `find-animation-opportunities` sweep on commit `ae63021` (001, 002) and a second-wave sweep on commit `d583fec` (003, 004).

001 and 002 landed together in commit `49cf74f`. 003 required a mid-implementation fix — see its Postmortem section: the planned `display: none ↔ block` + `@starting-style` approach didn't animate the open direction in real-browser testing (Chrome 152), so the discrete property was swapped to `visibility` instead. 004 was written to avoid that exact bug class by never toggling `display`/`visibility` (height animated via `grid-template-rows` directly on `<details>`) — but real-browser testing found a *different*, `<details>`-specific bug: it cannot smoothly transition `grid-template-rows` on itself at all, regardless of what triggers the change (native `[open]`, a same-tick class, or even a class deferred by one animation frame). See 004's Postmortem for the full isolation process. The fix that stuck was the native `::details-content` pseudo-element (Chrome 131+), which sidesteps the whole problem — no JS, no wrapper `<div>`, no `display`/`visibility` toggling.

## Recommended execution order

**004 is independent of 001/002/003** and can run any time — it's CSS-only, touches only `.inc-faq`-scoped selectors and one shared `@media (prefers-reduced-motion: reduce)` block, and shares no rule with any landed plan.

## Dependencies

None. 004 touches `src/app/globals.css` only inside `.inc-faq details`/`.inc-faq details::details-content`/`.inc-faq summary`/`.inc-faq details p` and adds two rules to the existing `@media (prefers-reduced-motion: reduce)` block — disjoint from where 001/002/003 made their edits. 003 touches `src/app/globals.css` only inside the existing `@media (max-width: 900px)` block and the same reduced-motion block — disjoint from where 001/002 made their edits.
