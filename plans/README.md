001 and 002 landed together in commit `49cf74f`. 003 required a mid-implementation fix — see its Postmortem section: the planned `display: none ↔ block` + `@starting-style` approach didn't animate the open direction in real-browser testing (Chrome 152), so the discrete property was swapped to `visibility` instead. 004 was written to avoid that exact bug class by never toggling `display`/`visibility` (height animated via `grid-template-rows` directly on `<details>`) — but real-browser testing found a *different*, `<details>`-specific bug: it cannot smoothly transition `grid-template-rows` on itself at all, regardless of what triggers the change (native `[open]`, a same-tick class, or even a class deferred by one animation frame). See 004's Postmortem for the full isolation process. The fix that stuck was the native `::details-content` pseudo-element (Chrome 131+), which sidesteps the whole problem — no JS, no wrapper `<div>`, no `display`/`visibility` toggling. 005 was a genuine new-DOM-mount entrance (not a `display`/`visibility` toggle, and not `<details>`-based), so neither prior bug class applied — but real-browser verification still caught a different, smaller bug: Tailwind v4's `translate-y-*`/`scale-*` utilities compile to the standalone CSS `translate`/`scale` properties, not `transform`, so listing `transform` in `transition-property` transitioned a property that never actually changed. Fixed by listing `translate,scale` instead. See 005's Postmortem. 006 uses a different mechanism again — a React `key`-driven remount triggering a plain `@keyframes` `animation` (no `transition`, no `@starting-style`) — and unlike 003-005, real-browser verification found no bug: it worked correctly on the first implementation attempt. See 006's Verification note.

## Recommended execution order

**004, 005, and 006 are all independent of 001/002/003 and of each other** and can run in any order. 004 is CSS-only, touching `.inc-faq`-scoped selectors in `globals.css`. 005 touches a single Tailwind `className` string in `ContactModal.tsx` and adds no CSS to `globals.css` at all. 006 touches `KazencoProjectMap.tsx`/`KazencoProjectMap.module.css`, a CSS Module pair untouched by any other plan in this series.
