001 and 002 landed together in commit `49cf74f`. 003 required a mid-implementation fix — see its Postmortem section: the planned `display: none ↔ block` + `@starting-style` approach didn't animate the open direction in real-browser testing (Chrome 152), so the discrete property was swapped to `visibility` instead. 004 was written to avoid that exact bug class by never toggling `display`/`visibility` (height animated via `grid-template-rows` directly on `<details>`) — but real-browser testing found a *different*, `<details>`-specific bug: it cannot smoothly transition `grid-template-rows` on itself at all, regardless of what triggers the change (native `[open]`, a same-tick class, or even a class deferred by one animation frame). See 004's Postmortem for the full isolation process. The fix that stuck was the native `::details-content` pseudo-element (Chrome 131+), which sidesteps the whole problem — no JS, no wrapper `<div>`, no `display`/`visibility` toggling. 005 was a genuine new-DOM-mount entrance (not a `display`/`visibility` toggle, and not `<details>`-based), so neither prior bug class applied — but real-browser verification still caught a different, smaller bug: Tailwind v4's `translate-y-*`/`scale-*` utilities compile to the standalone CSS `translate`/`scale` properties, not `transform`, so listing `transform` in `transition-property` transitioned a property that never actually changed. Fixed by listing `translate,scale` instead. See 005's Postmortem. 006 uses a different mechanism again — a React `key`-driven remount triggering a plain `@keyframes` `animation` (no `transition`, no `@starting-style`) — and unlike 003-005, real-browser verification found no bug: it worked correctly on the first implementation attempt. See 006's Verification note. 007 covers both directions of the project gallery lightbox (an earlier entrance-only version was deferred because the exit had nowhere to animate — instant unmount). Rather than a new technique, it deliberately reuses `FullScreenModal.tsx`'s proven `mounted`/`phase`/double-rAF/timeout mount-unmount mechanism (already working for the RFQ modal), adapted to `ProjectGallery`'s own CSS-Modules-only styling (an attribute-selector `data-phase` instead of FullScreenModal's inline-style approach) and its own easing/duration spec. Verification also caught and fixed a real, non-obvious bug the mechanism reuse itself surfaced: the existing focus-trap/scroll-lock effect was scoped to `isOpen`, which would have unlocked the background page while the lightbox was still visibly fading out — rescoped to `mounted` instead, confirmed via direct measurement that the background now stays locked for the full exit transition. A second, smaller gap was found and fixed under `prefers-reduced-motion`: the entrance's `data-phase` needed to be forced to `"open"` unconditionally when reduced motion is on (mirroring FullScreenModal's own `reduced ? CLIP_OPEN : ...` pattern exactly), rather than relying on `transition: none` alone, which left a 1-2 frame flash. See 007's Postmortem.

## Recommended execution order

**004, 005, 006, and 007 are all independent of 001/002/003 and of each other** and can run in any order. 004 is CSS-only, touching `.inc-faq`-scoped selectors in `globals.css`. 005 touches a single Tailwind `className` string in `ContactModal.tsx` and adds no CSS to `globals.css` at all. 006 touches `KazencoProjectMap.tsx`/`KazencoProjectMap.module.css`, a CSS Module pair untouched by any other plan in this series. 007 touches `ProjectGallery.tsx`/`ProjectGallery.module.css`, likewise untouched by any other plan — it reads `FullScreenModal.tsx` for reference but does not modify it.

None. 004 touches `src/app/globals.css` only inside `.inc-faq details`/`.inc-faq details::details-content`/`.inc-faq summary`/`.inc-faq details p` and adds two rules to the existing `@media (prefers-reduced-motion: reduce)` block — disjoint from where 001/002/003 made their edits. 003 touches `src/app/globals.css` only inside the existing `@media (max-width: 900px)` block and the same reduced-motion block — disjoint from where 001/002 made their edits. 005 touches only `src/components/ContactModal.tsx:443`, a file untouched by every other plan in this series. 006 touches only `src/components/KazencoProjectMap.tsx` and `src/components/KazencoProjectMap.module.css`, files untouched by every other plan in this series. 007 touches only `src/components/ProjectGallery.tsx` and `src/components/ProjectGallery.module.css`, files untouched by every other plan in this series (it reads, but does not write, `src/components/FullScreenModal.tsx`).
